# PRD: Drag and Drop в дереве Spaces

## 1. Назначение

Drag and Drop позволяет менять порядок элементов, переносить физические элементы, создавать ссылки и добавлять элементы как секции текущего focus.

Главный принцип: интерфейс должен показывать только то действие, которое действительно произойдёт после отпускания. Если состояние дерева не изменится, операция считается no-op: без индикатора вставки, без подписи действия, без сохранения данных и без задержки после drop.

## 2. Область действия

Правила распространяются на:

- обычные файлы;
- обычные папки;
- tag spaces;
- linked items;
- сепараторы;
- секции верхнего уровня текущего focus.

## 3. Термины

- **Контейнер** — папка или space, внутри которого отображаются дочерние элементы.
- **Текущий контейнер** — контейнер, в котором элемент находится в момент начала drag.
- **Focus level** — верхний уровень дерева, на котором элементы представлены как секции focus.
- **Reorder** — изменение позиции внутри того же контейнера без изменения принадлежности элемента.
- **Move** — физический перенос файла или папки в другой контейнер.
- **Copy** — создание физической копии в целевом контейнере.
- **Link** — добавление ссылки на существующий элемент без его физического перемещения.
- **Add to focus** — добавление существующего элемента как секции текущего focus без физического перемещения.
- **No-op** — drop, после которого данные и порядок элементов не меняются.
- **Линия вставки** — горизонтальный индикатор точной позиции между соседними элементами.
- **Подсветка контейнера** — визуальное обозначение, что элемент будет помещён внутрь контейнера.

## 4. Общие операции

Для обычного файла или папки:

| Контекст | Операция |
| --- | --- |
| Изменение позиции в текущем контейнере | Reorder |
| Drop в другую обычную папку | Move |
| Drop в другую папку с зажатым Shift | Link |
| Drop в другую папку с зажатым Alt/Option | Copy |
| Drop на focus level из вложенного контейнера | Add to focus |
| Drop элемента на самого себя | No-op |
| Drop внутрь физической родительской папки без позиции вставки | No-op |
| Drop в позицию, которую элемент уже занимает | No-op |

Элемент верхнего уровня focus по умолчанию перемещается только в рамках порядка секций.

## 5. Определение зоны drop

### 5.1. Точная позиция

Верхняя и нижняя зоны строки задают вставку до или после элемента. Если вставка изменяет порядок, показывается линия вставки.

Если вычисленная позиция совпадает с текущей позицией перетаскиваемого элемента, линия не показывается и drop становится no-op.

### 5.2. Drop внутрь контейнера

Центральная зона строки папки означает помещение внутрь папки, если это разрешено для перетаскиваемого типа.

Для раскрытой папки нижняя граница её строки может означать позицию перед первым дочерним элементом. Если перетаскиваемый элемент уже является первым ребёнком этой папки, такая зона является no-op и не должна показывать линию сверху первого элемента.

### 5.3. Свернутая папка

При наведении на свернутую папку подсвечивается вся папка как единая цель вместе с логически принадлежащими ей дочерними элементами. Правило одинаково для обычного space и tag space.

### 5.4. Drop на focus level

Drop между секциями задаёт точную позицию новой или перемещаемой секции.

Для вложенного обычного или linked элемента это действие означает Add to focus, а не физический перенос из исходной папки.

## 6. Обычные файлы и папки

### 6.1. Reorder

- Разрешён только при ручной сортировке контейнера.
- Линия вставки должна соответствовать итоговой позиции.
- Пересчёт позиции учитывает удаление исходного элемента из старого места до вставки в новое.
- Перемещение через сепаратор не должно сдвигать результат на одну дополнительную позицию.

### 6.2. Перенос в папку

- По умолчанию выполняется Move.
- С Shift выполняется Link.
- С Alt/Option выполняется Copy.
- Drop физического элемента в папку, которой он уже принадлежит, без нового места в порядке является no-op.

### 6.3. Защита от циклов

Папку нельзя поместить внутрь самой себя или любого своего потомка. Для такой цели не показывается допустимое действие.

## 7. Tag space

### 7.1. Разрешённые действия

| Контекст | Операция |
| --- | --- |
| Изменение позиции внутри текущего контейнера | Reorder |
| Drop в обычный допустимый контейнер | Link |
| Drop в самого себя | No-op |
| Drop на любой tag space | No-op |

Tag space нельзя физически переносить drag-операцией в другой контейнер. За пределами reorder Link разрешён только в обычный контейнер; любой tag space является no-op целью.

### 7.2. Модификаторы и подсказки

- Link является операцией по умолчанию.
- Alt/Option и Shift не меняют доступную операцию.
- Плашка с подсказкой `Hold…` во время drag не показывается.
- Reorder внутри текущего контейнера сохраняется и не должен ошибочно блокироваться правилом Link.

## 8. Linked item

Linked item — элемент, который отображается в контейнере как ссылка, а физически находится в другом месте.

### 8.1. Разрешённые действия

| Контекст | Операция |
| --- | --- |
| Изменение позиции внутри текущего контейнера | Reorder |
| Drop внутрь текущего контейнера без новой позиции | No-op |
| Drop в любую другую допустимую папку | Link |
| Drop на focus level | Add to focus |
| Попытка обычного физического переноса | Запрещено |

Linked item никогда не покидает физическое расположение через drag. Наведение на другую папку автоматически означает Link, независимо от клавиш-модификаторов.

### 8.2. Focus section

Linked item можно добавить на верхний уровень текущего focus как отдельную секцию. Действие отображается как `Add to <focus>` и не удаляет linked item из исходного контейнера.

### 8.3. Модификаторы и подсказки

- В текущем контейнере операция автоматически становится Reorder.
- В другой папке операция автоматически становится Link.
- На focus level операция автоматически становится Add to focus.
- Alt/Option и Shift не меняют это поведение.
- Плашка с подсказкой `Hold…` не показывается.

### 8.4. Ложные позиции

Если linked item уже стоит первым, наведение чуть выше него или на нижнюю границу родительской папки не должно показывать линию сверху и действие Reorder.

## 9. Сепаратор

### 9.1. Роль

Сепаратор — специальный элемент ручной структуры дерева. Он участвует в порядке элементов, но не является контейнером и не может принимать дочерние элементы.

### 9.2. Доступность

- Сепаратор отображается и участвует в DnD только при ручной сортировке.
- При любой другой сортировке сепаратор отсутствует в дереве и не является drop-целью.

### 9.3. Разрешённые действия

| Контекст | Операция |
| --- | --- |
| Изменение позиции в исходном контейнере | Reorder |
| Alt/Option + изменение позиции в исходном контейнере | Copy |
| Перенос в другую папку или tag space | Запрещено |
| Drop внутрь любой папки | Запрещено |
| Drop на самого себя | No-op |

Сепаратор можно переставлять только в том контейнере или на том focus level, где он был создан. Его нельзя использовать для Link.

### 9.4. Drop других элементов относительно сепаратора

- Сам сепаратор не принимает элементы внутрь.
- Другие элементы можно вставлять до или после сепаратора.
- При наведении на верхнюю часть сепаратора позиция «до сепаратора» визуально показывается как линия под предыдущим элементом.
- Физическая позиция после drop должна совпадать с визуальной линией.
- Пересчёт позиции обязан учитывать сам сепаратор, чтобы элемент не вставлялся на одну строку дальше ожидаемого.
- Несколько сепараторов в одном контейнере считаются независимыми экземплярами: drag одного не должен перемещать или удалять другой.

### 9.5. Drag hit area

- Высота строки сепаратора фиксирована и не зависит от пользовательской высоты обычной строки.
- Полная строка сепаратора должна равномерно захватываться выше и ниже визуальной линии.
- Нижняя часть hit area не должна преждевременно передавать drag следующему элементу.
- Hit area не должна иметь отдельного визуального смещения относительно строки.

### 9.6. Подсветка

- При drag сепаратора допустима подсветка только его родительского контейнера либо отсутствие подсветки.
- Другие папки не подсвечиваются как допустимые цели.
- При наведении сепаратора на собственную позицию родительская папка может оставаться подсвеченной, но операция остаётся no-op.
- Подсветка не должна выходить за визуальные границы родительской папки.
- При drag другого элемента над сепаратором сепаратор участвует в подсветке родительской папки так же, как остальные дочерние строки.

### 9.7. Drag ghost

- Drag ghost использует общий стиль ghost для файлов и папок.
- Вместо имени показывается только иконка горизонтального сепаратора.
- Текстовое имя отсутствует.
- Плашка `Hold…` не содержит подсказку про Link.
- Подпись `Reorder…` для сепаратора не показывается.

## 10. Визуальная обратная связь

### 10.1. Линия вставки

Линия показывается только для точной и реально изменяющей порядок позиции. Она не показывается:

- при drop на самого себя;
- при вставке в уже занимаемую позицию;
- при попытке поместить первый элемент перед самим собой;
- для запрещённой цели;
- для drop внутрь контейнера без позиционного действия.

### 10.2. Подсветка контейнера

Подсветка означает, что drop произойдёт внутрь указанного контейнера. Она не должна использоваться для запрещённой операции или создавать впечатление физического Move, когда фактически будет Link.

### 10.3. Подпись действия

Подпись должна описывать итоговую операцию после применения всех ограничений:

- `Reorder in …` — только если порядок действительно изменится;
- `Move to …` — физический перенос;
- `Copy to …` — физическая копия;
- `Link to …` — создание ссылки;
- `Add to …` — добавление секции в focus.

Для no-op подпись отсутствует.

### 10.4. Завершение drag

После mouse up или drop всегда немедленно удаляются:

- drag ghost;
- специальный курсор drag;
- линия вставки;
- подсветка цели;
- подпись действия.

Это правило действует и для успешной операции, и для no-op, и для запрещённой цели.

## 11. No-op и производительность

No-op должен определяться до сохранения или перестроения дерева.

К no-op относятся как минимум:

- drop элемента на самого себя;
- drop в текущую физическую родительскую папку без изменения позиции;
- reorder на тот же индекс;
- попытка поставить первый дочерний элемент перед самим собой;
- drop tag space внутрь самого себя, родительского или предкового tag space;
- drop linked item внутрь текущего контейнера без новой позиции;
- drop сепаратора на собственную позицию;
- любая запрещённая операция.

No-op не должен:

- изменять rank;
- сохранять metadata или focus;
- запускать файловую операцию;
- инициировать полную перезагрузку дерева;
- оставлять интерфейс в состоянии обработки;
- вызывать заметную задержку после отпускания.

## 12. Согласованность визуального и фактического результата

Перед выполнением drop система повторно проверяет те же ограничения, которые использовались для предпросмотра. Нельзя выполнять fallback-операцию, отличающуюся от последнего показанного действия.

Обязательные инварианты:

- если показана линия, элемент оказывается ровно в этой позиции;
- если подсвечена папка, операция выполняется именно относительно этой папки;
- если действие отсутствует, данные не меняются;
- Link никогда не превращается в Move после отпускания;
- запрещённый перенос сепаратора не выполняется через запасной сценарий;
- одинаково выглядящие сепараторы сохраняют независимую идентичность;
- вычисление позиции учитывает удаление исходного элемента и специальные строки дерева.

## 13. Критерии приёмки

1. Все допустимые операции имеют однозначную визуальную индикацию.
2. Все запрещённые и no-op операции завершаются мгновенно и без записи данных.
3. Фактическая позиция после drop совпадает с линией вставки.
4. Обычные элементы поддерживают Move, Copy, Link, Reorder и Add to focus согласно контексту.
5. Tag space поддерживает Reorder в своём контейнере и Link вне него, но не физический Move.
6. Linked item поддерживает только Reorder в своём контейнере, Link в другую папку и Add to focus.
7. Сепаратор поддерживает только Reorder или Copy в исходном контейнере.
8. Сепаратор не становится контейнером и не принимает элементы внутрь.
9. Несколько сепараторов можно независимо переставлять без исчезновения или подмены.
10. После любого завершения drag не остаются ghost, drag-курсор, подсветка или индикатор вставки.
11. Плашка `Hold…` отсутствует для tag space и linked item; для сепаратора она не предлагает Link.
12. Поведение одинаково для обычных spaces и tag spaces в тех случаях, где отдельное правило явно не задаёт различие.
